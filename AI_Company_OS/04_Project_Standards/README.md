# 04 — Project Standards

## Purpose

Company-wide rules for code, folders, naming, assets, prompts, and recipes.

## When to use

- Starting a new app or package
- Reviewing PRs for consistency
- Onboarding contributors

## How to use

1. Read the relevant standard before coding
2. Propose changes via a Decision doc if standards themselves change
3. Project-specific exceptions must be written as Decisions, not tribal knowledge
