# AI Company Knowledge OS

**Official knowledge management system for AI Company.**  
Not a product feature — the operating layer for every current and future project.

## Why this exists

So that no important **decision**, **architecture**, **engine**, **lesson**, or **reusable idea** is lost again.

## Folders

| # | Folder | Purpose |
| --- | --- | --- |
| 01 | [Decisions](./01_Decisions/) | Company decisions with why / impact / status |
| 02 | [Meeting Minutes](./02_Meeting_Minutes/) | Meeting records and action items |
| 03 | [Reusable Engines](./03_Reusable_Engines/) | Portable systems documented for reuse |
| 04 | [Project Standards](./04_Project_Standards/) | Coding, folders, naming, assets, prompts, recipes |
| 05 | [Best Practices](./05_Best_Practices/) | Workflows that worked |
| 06 | [Lessons Learned](./06_Lessons_Learned/) | Failures → prevention |
| 07 | [Future Ideas](./07_Future_Ideas/) | Ideas parked away from active sprints |
| 08 | [Roadmaps](./08_Roadmaps/) | One roadmap per project |
| 09 | [Templates](./09_Templates/) | Copy-paste document templates |
| 10 | [Assets](./10_Assets/) | Brand, characters, prompt libraries, design |

## Start here

1. Read **[Knowledge_Index.md](./Knowledge_Index.md)**
2. Copy a template from `09_Templates/` before writing a new doc
3. Link related files — never leave knowledge only in chat history

## Relationship to `docs/`

Legacy / deep product docs still live under repo `docs/` (e.g. HANKKI Bible, ADR-0001).  
**AI_Company_OS** is the **index + operating system**. New company-wide knowledge is written here first; link out to `docs/` when detail already exists.

## Rules

1. One concern per document  
2. Always fill required fields in the template  
3. Prefer links over copy-paste duplication  
4. Update Status when reality changes  
5. Park ideas in `07_Future_Ideas/` — do not interrupt the current sprint
